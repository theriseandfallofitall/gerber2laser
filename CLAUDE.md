# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Converts KiCad Gerber exports into laser-ready PNG/SVG for CO2 laser-resist etching (paint the board black, laser ablates paint where the image is black, chemical etch removes bare copper). The entire application is one file, `gerber2laser.py` — GUI, headless CLI, and KiCad action plugin in the same module.

Everything else is support: `assets/` (icon, generated by `tools/icons/make_icons.py` from `assets/gerber2laser.svg` — regenerate rather than hand-editing the PNG/ICO/ICNS), and `install/{windows,macos,linux}` (per-OS wizard installers; they build a venv, make a desktop item, and optionally drop the plugin into KiCad's user folder with a `.g2l_python` file pinning that venv, since a plugin can't set KiCad's environment).

## Commands

```powershell
# environment (repo has a .venv)
.venv\Scripts\python.exe -m pip install -r requirements.txt       # pyside6, gerbonara
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt   # pytest

# tests — pure core, no display needed (conftest.py forces Qt offscreen)
.venv\Scripts\python.exe -m pytest tests -q

# GUI
python gerber2laser.py
python gerber2laser.py --input Gerbers/        # GUI preloaded with a folder or zip

# headless CLI (the de-facto test harness — see Verification below)
python gerber2laser.py --input MyBoard/ --side front --png front.png
python gerber2laser.py --input MyBoard.zip --side back --reg --svg back.svg
python gerber2laser.py --input MyBoard/ --layers bottom_copper,outline,drill --kerf -0.05 --png back.png
python gerber2laser.py --coupon --png kerf_cal.png
python gerber2laser.py --help
```

`--layers` takes the loader's layer keys: `top_copper`, `bottom_copper`, `inner_copper`, `outline`, `f_silk`, `b_silk`, `f_mask`, `b_mask`, and one `drill1`, `drill2`, … per drill file found (`_CLASSIFY` emits `drill`; `load_layers` numbers them). Matching is exact-key *or* substring, so `--layers drill` catches them all and `--layers copper` catches all three copper keys.

`--side` only ticks layers; it does **not** run the GUI's `primary_copper_side()` auto-detection, so asking for a side the export has no copper for still writes an outline-only file. `run_cli` warns on stderr and names the side that is present — keep that warning if you touch `_apply_side`.

### Verification

There is no linter or build step. Two layers of checking:

- **`pytest tests -q`** — 253 tests, ~6 s. `tests/conftest.py` puts the repo root on `sys.path` and forces `QT_QPA_PLATFORM=offscreen` before anything can import PySide6, so no display is needed and no env var has to be set by the caller. It also writes a real 10×6 mm board (Edge.Cuts + F.Cu/B.Cu + PTH drill) to `tmp_path` via the `board_dir` / `back_board_dir` fixtures, so loader and `build_svg` tests run against genuine gerbonara parsing rather than mocks. Layout: `test_core.py` (filenames, kerf maths, RDP, `_is_dark`), `test_transform.py` (mirror/rotate), `test_colors.py` (`resolve_colors`/`layer_color`), `test_loader.py` (classification, loading, orientation verdict), `test_svg.py` (`svg_for_qt`, `build_svg` structure, the Invert boolean, coupon), `test_raster.py` (`rasterize_qimage`/`rasterize_png` size and pHYs DPI stamp, per-edge kerf, `_morph` exact disc, `--bg none` and typo fallback).
- **The headless CLI**, for anything the tests do not reach — chiefly real boards end to end and the GUI-only paths. Run it with `QT_QPA_PLATFORM=offscreen` (PowerShell: `$env:QT_QPA_PLATFORM='offscreen'`); everything except opening the actual Qt window works without a display.

Two traps when adding tests:

- **`_rdp` is O(n²) on incompressible input.** A dense zigzag makes every vertex a local extremum, so nothing can be dropped and a 30k-vertex path takes minutes. `svg_for_qt(svg, limit=N)` takes the cap as a parameter — drive the thinning tests through a small `limit` instead of building a real-sized path.
- **`_is_dark("#808080")` is `True`**, because the weighted luminance of the exact midpoint sums to `127.99999999999999` in float and the test is `< 128`. Pinned in `test_core.py` as documented behaviour, not as a semantic claim.
- **The Invert boolean has no cheap structural assertion.** Sub-path counts catch the coarse failures (the tests use them), but a wrong fill somewhere in the middle of a real board looks structurally fine. Verify it against the paint-over form: render both at the same DPI, threshold to masks, and require that *every* differing pixel sits on a boundary in one of them. Interior differences mean the boolean lost or gained area — that check is what turned up the winding bug, which a 0.2 % pixel diff otherwise hid.

## Architecture

`gerber2laser.py` is deliberately sectioned (marked by `# ---` banner comments); keep new code in the right section:

1. **Pure core (no Qt)** — `LayerCfg`/`RenderCfg` dataclasses, transform math (`build_transform`, mirror is about the board centre so front/back share one reference frame), `build_svg()` which produces the output SVG. Everything here must stay importable and testable headless. One exception: `_burn_field_d()` uses `QPainterPath` for the Invert polygon boolean, imported inside the function like every other PySide6 import — `QPainterPath` is geometry only, so it needs no display and no `QApplication`, and `build_svg()` falls back to the paint-over form with a `RuntimeWarning` if PySide6 is absent.
2. **`svg_for_qt()`** — thins paths before Qt sees them. QtSvg silently drops any path past ~41k vertices (KiCad zone pours hit this), which made pours vanish from preview *and* PNG export. Preview/PNG go through this thinning (2 µm tolerance); the exported SVG keeps full-fidelity geometry. Never route the SVG export through it.
3. **Calibration coupon** — self-contained SVG generator (kerf sweep, resolution ladder, scale bar).
4. **Loader** — files classified by *filename* (KiCad `-F_Cu.gbr` style, legacy `.gtl/.gbl/.gko`, `.drl`), from folder or zip, parsed with `gerbonara`. A common bounding box across layers keeps front and back aligned to the same origin.
5. **Orientation logic** — which copper side has geometry → whether horizontal mirror is required (back/single-sided boards must be mirrored or they etch reversed).
6. **Rasterization** — QSvgRenderer → QImage at true DPI; kerf is raster morphology applied *here only*.
7. **GUI** (`run_gui`) / **CLI** (`run_cli`) / **`main()`** dispatch.
8. **KiCad ActionPlugin** — registers "Gerber → Laser" in pcbnew when the file is imported inside KiCad; plots the open board's Gerbers + drills, then launches the GUI in an *external* Python (first `python` on PATH that can `import PySide6, gerbonara`, or `G2L_PYTHON` env var), because KiCad's bundled Python has neither.

### Import discipline (dual-mode file)

The file must import cleanly in three environments: full venv, KiCad's bundled Python (no PySide6/gerbonara), and outside pcbnew (no `pcbnew`). Hence:
- `gerbonara` and `pcbnew` imports are guarded try/except at module level.
- All PySide6 imports live *inside* functions, never at module top level. Keep it that way.

### Domain invariants

- **Black = laser fires = paint removed = copper etched.** The Invert toggle flips traces/gaps; in invert mode only the board area is the burn field and the margin keeps its own colour (`--invert-margin`).
- **Invert has two forms, and they are not interchangeable** — `build_svg(cfg, merge_invert=...)`:
  - **Export (`True`, the default)**: one `<path>` in the burn colour = board **minus** the copper **plus** the drills, computed by `_burn_field_d()`. The paper-coloured margin rect is dropped with it. LightBurn maps colour → layer and fills each layer on its own; it has no painter's model, so the old white-on-black knock-out arrived as two unrelated layers (white is not even in LightBurn's palette, so all of it snapped onto one nearest-match layer) and nothing subtracted — that is the bug this form exists to fix.
  - **Raster/preview (`False`)**: the paint-over composition — opaque burn rect, features repainted in the paper colour on top. Correct for a raster, and required for Qt: `svg_for_qt()` can only thin plain M/L polylines, so one merged path of that size would be dropped silently and take the whole board with it. `run_cli` builds both when `--svg` and `--png` are asked for together; the GUI preview and PNG export pass `False`.
- **The Invert field is a real polygon boolean, never a fill rule.** Copper overlaps itself constantly — a polyline's segments share round end caps, pads sit on traces, traces run through a pour — and *both* SVG fill rules read an overlap as a change of depth. Even-odd punches every trace junction and the whole inside of a zone pour back out to burn; nonzero cannot express difference-against-a-union at all. `_burn_field_d()` unions with `QPainterPath.simplified()`, then `subtracted()`/`united()`, in that order so a drill inside a trace comes back as a burn island.
- **Merged outlines are normalised counter-clockwise** (`_merged_outlines` → `_signed_area`). gerbonara promises no orientation: a `Rectangle` comes out in a fixed order, an `ArcPoly` keeps whatever direction the Gerber region contour had. Under the winding fill the union uses, a clockwise pad overlapping a counter-clockwise region cancels to zero and that copper silently becomes burn. Safe to flip because an `ArcPoly` holds exactly one contour and copper holes arrive as clear polarity, which is skipped.
- **Colour resolution lives in `resolve_colors()`** — it returns `[(layer, colour)]` in paint order (copper, other classes, drills last) and is the single source of truth for both `build_svg()` and the GUI swatches. Invert swaps black↔white layers only (`layer_color()`); feature-class colours (Edge.Cuts red, mask green) ride through untouched. **Drills have no colour of their own** — always the opposite of the copper (or of the board background when no copper layer is on), drawn last, so a hole punches through and reads as a hole in either mode. A colour the user picked by hand (`LayerCfg.color_overridden`, set by the GUI colour button or CLI `--layer-color KEY=COLOUR`) overrides all of that and is used verbatim.
- **Kerf is raster-only.** PNG export and raster preview get kerf; the SVG export is always exact geometry (LightBurn applies its own kerf offset). Kerf is per-edge: value `k` moves every black boundary by `k` mm, so a bar width changes by `2k`.
- **SVG output is one flat root `<svg>`** (no nested `<svg>`), one colour per feature class — LightBurn maps colour → cut layer. Keep it that way for Qt/Inkscape/LightBurn compatibility.
- **Feature geometry is FILLED, never stroked.** LightBurn ignores `stroke-width`, so a gerbonara-style centreline `<path stroke-width="0.5">` imports as a hairline and fills to nothing. `_layer_fragment()` converts every stroked primitive to its exact filled outline via gerbonara's `to_arc_poly()` (stadium/annulus, no approximation) instead of calling `GerberFile.to_svg()`. Exception: `outline` (Edge.Cuts) stays a centreline stroke — that's the path LightBurn should cut along. Second exception: geometry entering the Invert boolean is flattened to `MERGE_ARC_TOLERANCE_MM` (1 µm — twenty times under a 0.02 mm kerf), since the boolean works on polygons.
- **Back side = horizontal mirror auto-enabled**; registration crosshairs live in board coordinates so they ride through mirror/rotate.
- **Scale bar** is on by default (`--no-scale-bar` turns it off) and is drawn *outside* the transform group in the output frame (never mirrored, always true length), as its own `<g id="scale-bar">` in its own colour so LightBurn can map it to a no-output layer or the user can delete it. With registration marks on it sits in the strip they already open up below the board — level with the bottom crosshairs, starting clear of the left one — so it costs no extra output height; only without them (or if that strip is shallower than the bar's ink) does it add a band of its own.
- **PNG exports carry their DPI** (`setDotsPerMeterX/Y` → pHYs chunk), so LightBurn/Inkscape place the image at true board size instead of assuming 96 DPI. Don't drop this when touching `rasterize_qimage()`.
- **Drill marks are resizable** (`drill_size_mm` forces one diameter, `drill_scale` multiplies) via `_resize_hole()`, applied to drill layers only, before the fill conversion. It rewrites the gerbonara primitive, so it changes the SVG too — this is *geometry*, unlike kerf which is raster-only.
- **Export names encode the settings** (`settings_tags()` + `export_filename()`), capped at 100 chars: Windows' 260-char path limit is the binding constraint, so tags drop least-important-last-first before the board name is touched.
- **All labels are stroke-font `<path>`s** (`_text`/`_FONT`), never SVG `<text>` — QtSvg silently drops `<text>` (labels vanish from PNG/raster preview) and LightBurn ignores it too.

## Repo conventions

- `.gitattributes` forces LF on all text files (`* text=auto eol=lf`) because Windows and Linux KiCad disagree on line endings. Don't fight it.
- `.gitignore` blanket-ignores `*.png`/`*.svg` and re-adds `assets/*` — the icon set is source, not an export. A new asset outside `assets/` needs its own negation or it silently never commits.

## Repo layout (keep it organised)

Checked by `.githooks/layout_check.py` (settings in `.layout.json`), run by `.githooks/pre-commit` on
every commit (turn on once per clone: `git config core.hooksPath .githooks`). A failure is fixed by
moving or documenting the file, never by loosening the check or committing with `--no-verify`
without the owner's say-so.

- **Root** holds only the files in `.layout.json` `rootFiles`. Everything else goes in a folder. `gerber2laser.py` stays at the root: the installers, the KiCad plugin copy and `tests/conftest.py` all expect it there.
- **Folders:** each has one job, written in README, Repo map. A new top-level folder only when none
  fits, added to the map in the same commit.
- **Docs:** `README.md` stays a short overview, a Repo map and a Docs index; detail goes in `docs/`,
  one doc per area, each with a row in README, Docs. Rule docs UPPER-CASE, the rest lower-case kebab.
  Research in `docs/research/`, finished trackers and task lists in `docs/archive/`. Write about a
  topic in the doc that owns it; link, do not repeat.
- **Open work** lives in `TODO.md`; a one-off task list is
  archived when done.
- **Scripts and tests:** scripts in their group folder (`.layout.json` `groupedDirs`), never loose;
  each named in the code map when there is one. Tests are `tests/test_<area>.py` (pytest discovers them), shared fixtures in `tests/conftest.py`; helpers and fixtures in their subfolders.
- **Generated output and scratch** never go in git; add them to `.gitignore`. Temp files go outside
  the repo.
- **Moving things:** allowed when it makes the layout clearer. In the same commit: update every
  mention (`git grep` the old path; the check fails on a backticked path that no longer exists) and
  add old → new rows to `docs/moves.md`, with what else changes outside the repo. Other repos,
  servers and LLM sessions use that log to fix their paths. A path in another repo is written with
  its repo name (`other-repo/docs/...`).
- **Keep stable across moves:** anything that is an id or a URL rather than just a file (public
  URLs, API paths, ids stored in data, package or module names other code imports, deploy entry
  points). Move the file, keep the id or URL, or add a redirect and a `docs/moves.md` row.
